# Deep Interview Question Templates

심층 인터뷰를 위한 질문 템플릿과 체크리스트.
이 템플릿들은 **참조용**이며, 실제 질문은 문서/코드베이스 분석 결과를 바탕으로 맥락화되어야 합니다.

## 기술적 구현 (Technical Implementation)

### 아키텍처
- "[기능]의 데이터 흐름이 명시되지 않았는데, 동기/비동기 중 어떤 방식을 선호하시나요?"
- "현재 코드베이스가 [패턴A]를 사용하는데, [신규 기능]도 동일하게 할지, [패턴B]로 마이그레이션할지 결정이 필요합니다."
- "[외부 서비스]와의 통합 방식이 불명확합니다. 직접 호출 vs 메시지 큐 vs 이벤트 기반 중 선호하는 방식이 있으신가요?"

### 데이터 모델
- "[엔티티A]와 [엔티티B]의 관계가 1:N인지 N:M인지 명확하지 않습니다. 어떤 관계인가요?"
- "삭제된 데이터를 어떻게 처리할까요? 하드 삭제 vs 소프트 삭제(deleted_at)"
- "[필드]의 변경 이력을 추적해야 하나요? (audit log 필요 여부)"

### API 설계
- "API 버저닝 전략이 필요한가요? URL 경로(/v1/) vs 헤더 vs 쿼리 파라미터"
- "페이지네이션 방식을 offset 기반으로 할지, cursor 기반으로 할지 정해야 합니다."
- "벌크 작업 API가 필요한가요? (예: 여러 항목 일괄 삭제)"

### 상태 관리
- "클라이언트 상태와 서버 상태를 어떻게 분리할 계획인가요?"
- "캐싱 전략이 필요한가요? 필요하다면 캐시 무효화는 어떻게 처리할까요?"
- "오프라인 지원이 필요한가요? 필요하다면 동기화 충돌은 어떻게 해결할까요?"

## UI & UX (User Interface & Experience)

### 사용자 흐름
- "[작업]을 완료하기 위한 최소 단계 수를 정의했나요? 현재 흐름이 최적인가요?"
- "중간에 이탈한 사용자가 돌아왔을 때 진행 상태를 복원해야 하나요?"
- "권한이 없는 기능에 접근 시 어떻게 처리할까요? (숨기기 vs 비활성화 vs 안내 메시지)"

### 인터페이스 패턴
- "이 작업을 모달로 처리할지, 별도 페이지로 처리할지 결정이 필요합니다."
- "폼 제출 후 같은 페이지에 머물지, 다른 페이지로 이동할지 어떻게 할까요?"
- "데이터 목록의 정렬/필터 상태를 URL에 반영해야 하나요? (공유 가능 링크)"

### 로딩 & 피드백
- "데이터 로딩 중 스켈레톤 UI vs 스피너 vs 프로그레스 바 중 선호하는 방식이 있나요?"
- "옵티미스틱 업데이트를 적용할 작업이 있나요? (저장 전 UI 먼저 업데이트)"
- "긴 작업의 진행 상황을 어떻게 표시할까요? (진행률 vs 단계 표시)"

### 에러 처리
- "에러 발생 시 토스트 메시지 vs 인라인 에러 vs 전용 에러 페이지 중 어떤 방식을 선호하시나요?"
- "네트워크 오류 시 자동 재시도를 할까요? 몇 번까지?"
- "세션 만료 시 현재 작업을 저장하고 로그인 후 복원해야 하나요?"

### 접근성
- "키보드만으로 모든 기능을 사용할 수 있어야 하나요?"
- "스크린 리더 지원이 필요한가요? 지원 범위는?"
- "색상에만 의존하지 않는 정보 전달이 필요한가요? (색맹 고려)"

## 우려 사항 (Concerns)

### 보안
- "민감한 데이터(개인정보, 결제정보)의 암호화 범위를 정의해야 합니다."
- "API 인증 실패 시 구체적인 오류 메시지를 반환할까요, 아니면 보안상 모호하게 처리할까요?"
- "CSRF, XSS, SQL Injection 외에 특별히 고려해야 할 보안 위협이 있나요?"
- "감사 로그(audit log)가 필요한 작업은 무엇인가요?"

### 성능
- "목표 응답 시간이 있나요? (예: 95% 요청이 200ms 이내)"
- "동시 사용자 수 예상치가 있나요? 피크 시간대는?"
- "대용량 데이터 처리가 필요한 기능이 있나요? 배치 처리 vs 스트리밍"
- "이미지/파일 최적화 전략이 필요한가요? (리사이징, 압축, CDN)"

### 확장성
- "향후 다국어 지원이 필요한가요? 필요하다면 지금부터 i18n을 고려할까요?"
- "멀티 테넌시 지원이 필요한가요? (데이터 격리 수준)"
- "수평 확장을 고려해야 하나요? 세션 상태는 어떻게 관리할까요?"

### 유지보수성
- "기능 플래그(feature flag)를 사용할 계획인가요?"
- "A/B 테스트 인프라가 필요한가요?"
- "로깅 전략과 모니터링 범위를 정의해야 합니다."

### 엣지 케이스
- "[외부 서비스]가 응답하지 않을 때 폴백 전략이 필요합니다."
- "동시에 같은 데이터를 수정하려 할 때 어떻게 처리할까요? (낙관적 락 vs 비관적 락)"
- "데이터 마이그레이션 중 서비스 중단 없이 처리해야 하나요?"

## 트레이드오프 (Trade-offs)

### 복잡도 vs 성능
- "캐싱을 추가하면 성능은 향상되지만 복잡도가 증가합니다. 수용 가능한가요?"
- "비정규화로 조회 성능을 높일 수 있지만 데이터 일관성 유지가 어려워집니다. 어떻게 할까요?"
- "인덱스를 추가하면 조회는 빨라지지만 쓰기가 느려집니다. 어떤 패턴이 더 많나요?"

### 개발 속도 vs 코드 품질
- "MVP에서 테스트 커버리지 목표를 어느 정도로 설정할까요?"
- "기술 부채를 감수하고 빠르게 출시할지, 시간이 더 걸리더라도 견고하게 만들지 결정이 필요합니다."
- "문서화 범위를 어디까지 할까요? (API 문서 vs 아키텍처 문서 vs 코드 주석)"

### 단순성 vs 유연성
- "설정 가능한 옵션을 많이 제공할지, 의견이 있는(opinionated) 단순한 방식으로 갈지 결정이 필요합니다."
- "플러그인/확장 시스템이 필요한가요? 아니면 하드코딩된 통합으로 충분한가요?"
- "제네릭한 솔루션 vs 특정 유스케이스에 최적화된 솔루션, 어떤 방향인가요?"

### 기능 범위 vs 출시 시간
- "MVP에 반드시 포함되어야 할 기능과 나중에 추가해도 될 기능을 구분해야 합니다."
- "[기능]을 초기 버전에서 제외하면 출시를 [기간] 앞당길 수 있습니다. 어떻게 할까요?"
- "이 기능 없이 출시했을 때 사용자 경험에 치명적인가요?"

### 사용자 편의 vs 보안
- "자동 로그인 유지를 허용할까요? 보안 위험과 편의성 사이의 균형은?"
- "비밀번호 복잡도 요구사항을 어느 수준으로 설정할까요?"
- "2단계 인증을 필수로 할까요, 선택으로 할까요?"

## 인터뷰 완료 체크리스트

인터뷰 종료 전 확인:
- [ ] 모든 "TBD", "TODO" 항목이 해결되었는가?
- [ ] 핵심 아키텍처 결정이 완료되었는가?
- [ ] MVP 범위가 명확한가?
- [ ] 주요 트레이드오프가 합의되었는가?
- [ ] 보안 관련 요구사항이 정의되었는가?
- [ ] 에러/예외 처리 전략이 정의되었는가?
- [ ] 비기능적 요구사항(성능, 확장성)이 정의되었는가?
